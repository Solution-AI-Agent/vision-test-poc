## 판단

## 실제 화면과 행동

`act-final.png` 직접 확인: 수량221이 선택된 상태, 요구값2가 아님. 이름/이메일은 이 진단의 범위 밖이며 비어 있음.

1. 수량칸 클릭(136,445).
2. type2로 기존1 앞에 삽입되어21.
3. 다시 type2로221.
4. 모델이 ctrl a와 backspace를 함께 요청. ctrl a만 네 번째 행동으로 실행되고, backspace는 행동한도에 차단됨.

모델 finished 없음, assertion 미실행, 실행 상태 limited-incomplete. 모델은 입력 누적을 알아차리고 교정하려 했으므로 더 긴 한도에서도 실패한다고 주장할 수 없다. 기록의 typedValues=2 및 mode=replace는 화면 확인이나 실제 교체 실행의 증거가 아니다.

## 일련의 실험 결론

- 별도 JSON 계획 누락을 피하고 UI-TARS 단독으로 실제 행동 실행: 확인.
- 모델 이력에 정규화 좌표가 섞이는 구현 문제: 모의 재현/수정 검증. 수정 후 실제 이메일 위치 클릭도1회 확인했으나 단독 인과 효과는 미확정.
- up 키 별칭 호환 문제: 실제 실패 재현 및 SDK/브라우저 모의 재생 수정 검증.
- 전체 주문: 서로 다른 수정단계 실제4회 모두 미완료. 단일 수량 입력 추가1회도 정해진4행동 내 미완료.
- 직접 행동 실험 전체5회의 공급자41요청, 보고비용 $0.0329124. 서로 다른 조건이므로 성공률 통계로 쓰지 않는다. earlier demand 비교2호출 비용은 이 합계에서 제외.
- 시각 결함 검출: 이 직접 행동 실험에서 검증되지 않음.

POC_MAKER에 결과를 전달하고 현재 실험 종료/보존을 요청했다. 추가 프롬프트 후보, 유료 호출, 한도 증대, 운영 앱 반영은 하지 않는다. .env는 사용자 지시대로 유지/Git 제외한다.

다음 수정 검토의 권고는 입력 동작 계약 정리이다: UI-TARS type의 실제 삽입 동작과 SDK mode=replace 표시를 구분하고, 명시적인 입력 교체 보조가 필요한지 검토한다. 모델이 요청하지 않은 자동 지우기를 이번 결과에 소급 도입하거나 성공으로 표시하지 않는다.
