## 판단

일반 입력 지침 후보는 이번 실행에서 주문 완료를 복구하지 못했으므로 앱에 채택하지 않는다. 전체 주문 프롬프트를 계속 늘리는 실험은 중단하고, UI-TARS 단독으로 단일 수량 입력을 할 수 있는지로 다음 진단 단위를 축소한다. 기존 주문 성공 기준을 단일 입력 성공으로 바꾸지는 않는다.

## 검증과 결과

- HEAD `930693b6b22375170f2e72790947c4b233a791cb`, clean. 같은 셸에서 HEAD를 기록하고 독립 전체 테스트 platform86/sample3/shared UI typecheck와 root build 통과.
- 일반 지침은 기존 default 문구를 보존해 aiContexts.aiAct에 추가하며 사용자 원문/한도는 유지. assert에는 추가하지 않음. 모의 요청 비교 검증 통과.
- 무과금 preflight `0dcb3662-eb08-4eb3-8949-52317b690a4c`와 실제 run `aac844ec-7522-43b7-bbd8-381ca7a249f2` 구분.
- 실제 원장: `REPOS/vision-test-maker/artifacts/aac844ec-7522-43b7-bbd8-381ca7a249f2/ACT_EXPERIMENT.json`.
- 2026-10-08T02:48:52.409Z–02:49:48.264Z, 55.855초, 13호출/12실행행동, 128,399토큰, 보고 비용 $0.0129323.
- 첫 상품 클릭 후 수량칸(136,446)을11번 클릭. 요청3~13의 설명과 행동이 동일하며 수량칸이 보이지 않는다고 주장함. 13번째 요청에서 추가 행동은 한도로 차단됨.

## 비교 한계

직전 baseline `9ed22220`(a534d27)은 수량2/김성지까지 입력하고 이메일 placeholder 삭제 반복으로 종료했다. 이번 input-guidance는 수량 클릭 반복으로 종료했다. 서로 다른 실행의1회 표본으로 지침의 일반적 인과 효과나 악화를 단정할 수 없다. 다만 해당 변형을 현재 앱에 채택할 성공 근거는 없다.

지금까지 직접 행동 경로의 서로 다른 수정 단계 실제4회 모두 주문 미완료: e4c62a7f/7bb207d3/9ed22220/aac844ec. 합계37모델 호출, 비용 $0.0313924. 동일 조건 반복 실험의 성공률 통계가 아니다.

## 후속 범위

POC_MAKER에 기존 scenario 옵션을 활용한 ‘수량을 2로 입력한다.’ 단일 입력 진단의 최소 명령 준비를 위임했다. guidance=false, 새 세션의 원래 Store D 전체 화면, 같은 모델, 6요청·4행동·90초, DOM/고정좌표/자동삭제 없음. 모의 사전검증 후 실행 가능하도록 준비하되 Maker의 유료 호출/운영 앱 반영은 없음. 긴 업무·이력 문제와 단일 조작 능력을 분리하는 진단이며 주문 완료·결함 검출을 대신하지 않는다.
