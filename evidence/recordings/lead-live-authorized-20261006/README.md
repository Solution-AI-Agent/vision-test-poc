## 확인한 원인과 범위

배포 코드 3e1138a의 같은 한국어 A/C/D/E/F/G 화면을 직접 시험했습니다. 초기 QA 응답에서 C/D/G는 결함 설명 자체가 없었습니다. 이번 미탐은 좌표 검증에서 후보가 사라진 경우가 아닙니다. F는 네트워크 실패여서 모델 판정이 없습니다.

같은 저장 JPEG에서 관찰 우선 지시, 같은 요청의 235B 모델, 정상 A를 추가한 참조 비교를 별도 실행했습니다. 참조 비교는 C와 D를 지적했으나 E/G 미탐과 E 오탐이 남았습니다. F는 색상 차이를 의심했지만 상품 설명과 이미지의 모순을 충분히 설명하지 못했습니다. 더 큰 모델 또는 더 강한 지시만으로 해결했다고 볼 수 없습니다. 이는 등록된 정상 기준을 쓰는 비교 진단이며 무참조 자율 검출 성공이 아닙니다.

reference-compare/*.svg는 실제 모델이 반환한 bbox_1000을 변환한 표시입니다. C 박스가 변형 전체를 정확히 감싸지는 않고 D 박스가 중복됩니다. 원본 JPEG는 수정하지 않았습니다. 케이스 문자는 실행 후 사람이 정리한 식별자이며 판독 프롬프트에 결함 정답을 넣지 않았습니다. 원문·프롬프트·요청 이미지 해시는 각 JSON에 있습니다.

## 입력 동작

실제 Qwen 계획은 0~1000 정규화 좌표였는데 기존 실행기는 픽셀로 사용했습니다. 또한 기존 insertText는 수량을 교체하지 않고 덧붙일 수 있었습니다. 64dc098은 좌표 계약을 명시해 변환하고 포커스→전체 선택→입력을 별도 행동으로 집계합니다. 실제 quantity-check는 수량 1→2, 합계 $24, 모델의 입력 확인 및 완료까지 도달했습니다(6요청/3행동). 이 실행에서도 정상 화면 헤더에 잘못된 의심이 발생해 시각 QA 신뢰성은 별개입니다.

order-check는 수량 변경 후 이름 입력칸 가장자리를 누르는 실패와 후속 모델 네트워크 실패로 주문을 마치지 못했습니다. 원본을 보존했습니다. e00a387 실행은 수량과 이메일을 정확히 입력하고 한국어로 설명했지만, 이름 공란·미제출 상태를 완료로 오판했습니다. 사람이 직접 최종 화면을 확인해 업무 실패로 분류하며 raw completed와 분리합니다. e00a387은 새 화면에서 편집 가능한 입력칸 내부 위치를 별도로 찾고, Midscene 기본 언어를 Korean으로 지정합니다. 후속 9b7040f는 pass 전 별도 완료 확인을 추가하고 동일한 관찰/기대의 정상 내용을 후보에서 제외했습니다. order-final-check는 이 수정의 1회 확인입니다. order-final-check도 이름·이메일 공란인데 독립 완료 검사가 true를 반환했습니다. 같은 모델의 재확인은 보증이 아닙니다. 후속 코드는 pass와 미실행 click/type 등이 함께 있는 모순을 성공으로 처리하지 않도록 차단했으며 추가 실호출은 하지 않았습니다. 각 실행의 실제 결과는 SUMMARY.json과 RUN.json에 별도로 기록합니다. 각 시도는 정해진 호출·시간 한도 안에서 1회 진행했습니다.

## 파일

- a.json … g.json / BASELINE_SUMMARY.json: 수정 전 배포 코드 실제 실행
