# 선택·입력 실행 구분과 설정 확인

코드: c0cacb43a3a2e28743f6352caa1be2e11446f007.

상품 선택을 문자 입력으로 분류해 다른 입력칸을 편집했던 재현에 대한 보완이다. 선택 단계를 별도 kind로 정의하고 실제 실행 전에 Midscene 화면 관찰로 editable/choice/unknown과 현재 값을 읽는다. 관찰상 선택 컨트롤이면 문자 입력 대신 선택 경로를 사용한다. 이미 선택된 항목은 값을 확인하고 계속한다. 대상이 불명확하거나 선택 후 값이 다르면 중단한다. 케이스별 정답·DOM locator를 추가하지 않았다. 추가 화면 관찰은 기존 모델 호출 한도를 사용한다.

## 사용 설정

1. 플랫폼의 왼쪽 **모델 & 설정**을 연다.
2. **웹 겹침 보조 검사**에서 **웹 위치 + 화면 혼합 검사**를 고른다.
3. **지침·설정 저장**을 누른다. 저장 완료 안내를 확인한다.
4. 새 시나리오 실행을 시작한다. 기존 실행에 소급 적용되지 않는다.

설정은 `.data/settings.json`에 유지되고 API 키는 재시작 후 다시 입력해야 한다. 위치 보조 검사의 의심은 모델의 정확한 설명이나 확정 결함과 같지 않다. 정상 A와 D를 함께 비교한다. 다단계 주문은 정밀 위치 탐색·값 확인·시각 QA 때문에 기본10호출을 넘을 수 있다.

## 검증과 제한

- 전체 플랫폼59 + 샘플3 = 62테스트 PASS, 공유 UI 타입 및 두 앱 빌드 PASS.
- 잘못된 input 분류를 choice로 보정, 이미 선택된 항목, 실제 선택 변경, 선택 결과 불일치, 불명확한 컨트롤을 회귀 검증했다. 모의 모델 검사다.
- 격리된 checkout에서 실제 Chromium UI로 혼합 설정 저장, API 값, 로컬 저장 파일, 서버 재시작 후 유지 및 데스크톱/모바일 표시를 확인했다. 페이지오류0, 실제 모델 호출0.
- 수정 후 실제 D 주문 모델 검증은 **미완료**. 최대40호출·15분 시험은 자동 승인 검토가 외부 화면/입력 전송과 추가 API비용 범위의 명시적 승인이 필요하다고 거절했다. 이 결과를 실제 주문 성공 또는 Vision 검출 성공으로 표현하지 않는다.
- 기존 D의 모델 미탐 및 기대결과/정상 앱 표시 위치 불일치는 별도 문제로 남아 있다.
